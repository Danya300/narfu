# Документация проекта: NARFU — Информационный портал объектов историко-архитектурного наследия

> **Полное название:** Сайт объектов историко-архитектурного наследия САФУ (Северный (Арктический) федеральный университет)
>
> **Стек:** Django 6.0 + Wagtail 7.3 CMS, Python 3.12+, SQLite (dev) / PostgreSQL (prod), Bootstrap 5, Leaflet 1.9, Pannellum 2.5, img-comparison-slider 8
>
> **Репозиторий:** `https://github.com/Danya300/narfu.git`
>
> **Тип:** Веб-приложение CMS для учёта и популяризации объектов культурного наследия Архангельской области

## 1. Определение требований, выбор технологий

### 1.1. Целевая аудитория

Проект ориентирован на следующие группы пользователей:

| Группа | Описание | Основные потребности |
|--------|----------|----------------------|
| **Студенты и преподаватели САФУ** | Исследователи истории, архитектуры, культурологии | Достоверная информация, цитируемый контент, медиаматериалы |
| **Жители Архангельской области** | Краеведы, туристы, местные жители | Карта объектов с адресами, описание и фотографии, маршруты |
| **Туристы** | Гости региона, посещающие исторические места | Навигация, панорамы 360°, видео-экскурсии |
| **Гос. и общественные организации** | Органы охраны культурного наследия | Учёт и систематизация объектов, формы обратной связи |
| **Контент-менеджеры** | Сотрудники САФУ, ответственные за наполнение | Удобная CMS, медиа-загрузка, мультимедийный контент |
| **Эксперты и партнёры** | Историки, реставраторы, спонсоры | Представление экспертного мнения, раздел «Партнёры» |

### 1.2. Сценарии использования (User Stories)

**Сценарий 1 — Просмотр списка объектов**
> Как посетитель сайта, я хочу открыть раздел «Объекты наследия» и увидеть список достопримечательностей с фотографиями и адресами, чтобы выбрать интересное для посещения.

**Сценарий 2 — Изучение конкретного объекта**
> Как пользователь, я хочу перейти на страницу объекта и увидеть подробное описание, галерею изображений, видео, 360° панораму и слайдер «до/после реставрации», чтобы получить полное впечатление о памятнике.

**Сценарий 3 — Просмотр объектов на карте**
> Как турист, я хочу увидеть все объекты на интерактивной карте с кластеризацией маркеров, чтобы спланировать маршрут.

**Сценарий 4 — Поиск**
> Как исследователь, я хочу воспользоваться поиском по названию, адресу, описанию или содержимому страниц, чтобы быстро найти нужную информацию.

**Сценарий 5 — Чтение новостей**
> Как подписчик, я хочу читать новости о реставрации, конференциях и событиях, отсортированные по дате.

**Сценарий 6 — Знакомство с экспертами и партнёрами**
> Как посетитель, я хочу увидеть раздел «Эксперты» и «Партнёры», чтобы понимать авторитетность проекта.

**Сценарий 7 — Связаться с командой**
> Как пользователь, я хочу найти контактные данные на странице «Контакты» и в футере сайта.

**Сценарий 8 — Адаптивный просмотр с мобильного**
> Как пользователь смартфона, я хочу комфортно просматривать сайт, смотреть панорамы 360° и аудио-экскурсии с возможностью перемотки.

### 1.3. Функциональные требования

- **FR1.** Отображение 7 разделов: Главная, О нас, Объекты наследия, Партнёры, Эксперты, Новости, Контакты.
- **FR2.** Детальная страница объекта с медиаконтентом (фото, видео, 360° панорамы, PDF, до/после).
- **FR3.** Интерактивная карта объектов (Leaflet + OpenStreetMap + кластеризация).
- **FR4.** Полнотекстовый поиск по всем страницам с пагинацией.
- **FR5.** Управление контентом через админку Wagtail.
- **FR6.** Загрузка больших файлов (панорамы 360° до 50 МБ).
- **FR7.** Поддержка HTTP Range-запросов для потокового воспроизведения медиа на мобильных.
- **FR8.** Адаптивная вёрстка (Mobile-first, breakpoints 576/768/992/1200).
- **FR9.** Встраивание видео с YouTube, RuTube, VK Video.
- **FR10.** Галерея-карусель на странице объекта.
- **FR11.** Управление футером через Snippet-админку.

### 1.4. Нефункциональные требования

- **NFR1.** Производительность: загрузка главной страницы < 2 сек при 50 объектах.
- **NFR2.** Доступность: соответствие WCAG 2.1 AA (`aria-label`, `visually-hidden`, alt-тексты).
- **NFR3.** SEO: семантическая вёрстка, уникальные заголовки, поддержка Wagtail Sitemap.
- **NFR4.** Безопасность: CSRF, XFrame-Options, валидация паролей Django.
- **NFR5.** Масштабируемость: переход с SQLite на PostgreSQL без изменения кода.
- **NFR6.** Контейнеризация: Dockerfile в комплекте.
- **NFR7.** i18n: `USE_I18N = True` (готово к локализации).

### 1.5. Сравнение технологических стеков

#### Вариант A: Django + Wagtail + PostgreSQL ✅ (выбран)

| Плюсы | Минусы |
|-------|--------|
| Мощная админка CMS из коробки (Wagtail 7.3) | Монолитная архитектура |
| StreamField — гибкий контент-конструктор | Сложнее масштабировать на микросервисы |
| Встроенный поиск, изображения, документы, формы | Высокий порог входа |
| SEO-готов (sitemaps, redirects) | Требует больше ресурсов, чем Node |
| Идеален для контентных проектов | — |
| **Огромное сообщество, документация** | — |

#### Вариант B: Node.js (Express/NestJS) + MySQL + Strapi CMS

| Плюсы | Минусы |
|-------|--------|
| Высокая производительность async I/O | Strapi платный для enterprise-фич |
| JavaScript fullstack | Менее зрелая CMS-экосистема |
| Лёгкий WebSocket / real-time | Сложнее SEO-friendly SSR |
| Огромная npm-экосистема | Сложнее типизация без TypeScript |

#### Вариант C: PHP (Laravel) + MySQL + October CMS

| Плюсы | Минусы |
|-------|--------|
| Простота развёртывания (shared hosting) | Производительность ниже Django/Node |
| Laravel — зрелый фреймворк | Меньше готовых «медиа»-функций (панорамы) |
| October CMS — Twig-шаблоны | October CMS менее популярен |
| Дешёвый хостинг | Сложнее поддерживать мультимедиа |

### 1.6. Обоснование выбора

**Выбран Django 6.0 + Wagtail 7.3 + SQLite (dev) / PostgreSQL (prod)**, потому что:

1. **Wagtail — лучшая CMS для медиа-контента.** StreamField позволяет контент-менеджеру собирать страницу из блоков (видео, панорама, сравнение, документ, галерея) без программиста — критично для краеведческого проекта.
2. **Django ORM + миграции** — простая смена БД (SQLite → PostgreSQL) без изменения кода.
3. **Daphne / Granian** — поддержка ASGI для будущего real-time.
4. **Встроенный админ-интерфейс Wagtail** избавляет от необходимости писать CRUD.
5. **Сильная типобезопасность моделей** (CharField, FloatField, StreamField) — меньше runtime-ошибок.
6. **Прямая интеграция с Leaflet/JS через шаблоны Django**.

**Frontend: Bootstrap 5 (CDN) + vanilla JS** — минимум зависимостей, быстрая загрузка.

**Принципы ООП в проекте:**
- **Наследование:** Все страницы наследуют `Page`, получая поля (`title`, `slug`, `live`, `path`, `depth`), URL-роутинг, версионирование ревизий и админку.
- **Инкапсуляция:** StreamField-блоки инкапсулируют UI-логику (template, icon, label) внутри себя.
- **Полиморфизм:** `Page.serve()` переопределяется через `get_context()` — разные типы страниц добавляют свой контекст.
- **Абстракция:** Работа с контентом абстрагирована через Wagtail ORM (`Page.objects.live()`).

## 4.2. Описание классов

### Класс `HeritageObjectPage` — центральная сущность

**Расположение:** `mysite/heritage_objects/models.py`

**Назначение:** Модель страницы объекта историко-архитектурного наследия.

**Принципы ООП:**
- **Наследование:** `HeritageObjectPage(Page)` — наследует все поля и методы Wagtail Page (URL-генерация, ревизии, админка, поиск).
- **Инкапсуляция:** `content_panels` инкапсулирует порядок полей в админке; `search_fields` — список индексируемых полей.
- **Полиморфизм:** Переопределение `get_context()` не требуется — стандартного поведения Page достаточно; список дочерних объектов выдаёт `HeritageObjectIndexPage.get_context()`.

**Поля:**

| Поле | Тип | Описание | Валидация |
|------|-----|----------|-----------|
| `address` | CharField(200) | Адрес объекта | `verbose_name`, обязательное |
| `phone` | CharField(50) | Контактный телефон | `blank=True` |
| `description` | TextField | Описание объекта | `blank=True` |
| `year_built` | CharField(50) | Год постройки | `blank=True` |
| `architectural_style` | CharField(100) | Стиль архитектуры | `blank=True` |
| `latitude` | FloatField | Широта для карты | `null=True, blank=True` |
| `longitude` | FloatField | Долгота для карты | `null=True, blank=True` |
| `map_link` | URLField | Ссылка на Яндекс.Карты | `blank=True` |
| `gallery` | StreamField | Галерея изображений | `blank=True` |
| `content` | StreamField | Гибкий контент (heading, paragraph, image, video, document, comparison, panorama) | `blank=True` |

**Метод `__str__`:** Наследуется от Page — возвращает `title`.

**Метод `get_context`:** Не переопределён, используется стандартный Page.

### Класс `HeritageObjectIndexPage` — индексная страница

**Назначение:** Родительская страница для коллекции объектов.

**Ключевой метод:**
```python
def get_context(self, request):
    context = super().get_context(request)
    heritage_objects = HeritageObjectPage.objects.live().child_of(self)
    context['heritage_objects'] = heritage_objects
    return context
```

**Полиморфизм:** Этот метод демонстрирует полиморфизм — переопределяет поведение родителя `Page.get_context()`, добавляя специфичную коллекцию в контекст шаблона.

### Класс `HomePage`

**StreamField `content`** состоит из следующих блоков:
- `heading` — CharBlock (заголовок H2)
- `paragraph` — RichTextBlock
- `image` — ImageChooserBlock
- `video` — VideoBlock (title + iframe + description)
- `video_file` — VideoFileBlock (title + файл + постер)
- `audio_file` — AudioFileBlock (title + аудио-файл)
- `news` — NewsBlock (title + content + date + image)
- `contact_info` — ContactInfoBlock (title + value + icon)

### Класс `NewsPage`

**Поля:**
- `date` — DateField
- `intro` — TextField (краткий анонс)
- `image` — ForeignKey → `wagtailimages.Image` (с `on_delete=SET_NULL` — изображение не удаляется при удалении новости)
- `content` — StreamField (heading, paragraph, image, video)

**Связи:**
- N:1 — `image → wagtailimages.Image`

### Класс `NewsIndexPage`

**Метод `get_context`:**
```python
def get_context(self, request):
    context = super().get_context(request)
    news_pages = NewsPage.objects.live().descendant_of(self).order_by('-date')
    context['news_pages'] = news_pages
    return context
```

**Логика:** Возвращает только опубликованные (`live=True`) дочерние страницы, отсортированные по убыванию даты.

### Класс `FooterSettings` (Singleton Snippet)

**Назначение:** Хранение настроек футера сайта (адрес, email, соц.сети).

**Особенности:** Не наследует `Page`, наследует `models.Model`. Используется как singleton (одна запись). Доступ через админку Wagtail Snippets.

### Block-классы (StructBlock)

Все блоки `home/models.py` и `heritage_objects/models.py` наследуют `wagtail.blocks.StructBlock` и реализуют принцип **инкапсуляции** UI-логики:

```python
class VideoBlock(blocks.StructBlock):
```

- `label` — название блока в UI

**Преимущества такого подхода:**
- Контент-менеджер просто выбирает тип блока в StreamField, без программирования.
- Любой блок можно переиспользовать на разных страницах.
- Изменение шаблона блока мгновенно отражается на всех страницах.

### 4.3.5. Примеры запросов

```sql
-- 1. Получить все опубликованные объекты с координатами
SELECT id, title, address, latitude, longitude
FROM heritage_objects_heritageobjectpage
WHERE page_ptr_id IN (SELECT id FROM wagtailcore_page WHERE live = TRUE)
  AND latitude IS NOT NULL
ORDER BY title;

-- 2. Найти объекты, построенные в XVIII веке (1700-1799)
SELECT title, year_built, address
FROM heritage_objects_heritageobjectpage
WHERE year_built ~ '^(17[0-9]{2})$'
ORDER BY year_built;

-- 3. Полнотекстовый поиск по объектам (PostgreSQL FTS)
SELECT
    p.title,
    p.url,
    ts_rank(idx.search_vector, plainto_tsquery('russian', 'деревянный')) AS rank
FROM wagtailsearch_indexentry idx
JOIN wagtailcore_page p ON p.id = idx.object_id
WHERE idx.search_vector @@ plainto_tsquery('russian', 'деревянный')
ORDER BY rank DESC
LIMIT 10;

-- 4. Получить 5 последних новостей
SELECT p.title, n.date, n.intro
FROM home_newspage n
JOIN wagtailcore_page p ON p.id = n.page_ptr_id
WHERE p.live = TRUE
ORDER BY n.date DESC
LIMIT 5;

-- 5. Связать объекты с их индексной страницей (parent)
SELECT
    child.title AS object_title,
    parent.title AS section_title,
    child.path
FROM wagtailcore_page child
JOIN wagtailcore_page parent
    ON child.path LIKE parent.path || '%'
    AND child.id != parent.id
    AND child.depth = parent.depth + 1
WHERE child.content_type_id = (SELECT id FROM django_content_type
                                WHERE app_label='heritage_objects'
                                AND model='heritageobjectpage')
  AND child.live = TRUE
ORDER BY parent.title, child.title;
```

### 4.5.1. Алгоритм поиска

**Расположение:** `mysite/search/views.py`

**Алгоритм (псевдокод):**

```
function search(request):
    query = request.GET.get("query", "").lower()
    page  = request.GET.get("page", 1)
    
    if query is empty:
        return empty results
    
    results = []
    for page in Page.objects.live().specific():
        if query in page.title.lower():
            add to results
        elif page has 'intro' and query in page.intro.lower():
            add to results
        elif page has 'description' and query in page.description.lower():
            add to results
        elif page has 'address' and query in page.address.lower():
            add to results
        elif page has 'content' and query in str(page.content).lower():
            add to results
        elif page has 'year_built' and query in page.year_built.lower():
            add to results
        elif page has 'architectural_style' and query in page.architectural_style.lower():
            add to results
    
    return paginated results (10 per page)
```

**Сложность:** O(N × M), где N — количество live-страниц, M — количество полей на странице. Для 50 объектов и 7 полей — около 350 сравнений на запрос. Приемлемо.

### 4.5.6. RangeRequestMiddleware (HTTP Range)

**Расположение:** `mysite/mysite/middleware.py`

**Назначение:** Поддержка `Range: bytes=0-1023` для аудио/видео-файлов, чтобы мобильные браузеры могли перематывать.

**Алгоритм:**
```
process_response(request, response):
    if request.method != GET: return response
    if response is FileResponse:
        response['Accept-Ranges'] = 'bytes'
        range_header = request.META.get('HTTP_RANGE')
        if not range_header: return response
        # Парсинг range
        start, end = parse_range(range_header, file_size)
        # Возврат 206 Partial Content
        return partial_response(start, end, file_size)
    else:
        return add_accept_ranges_header(response, request)
```

**Поддерживаемые форматы:** `.mp3, .mp4, .webm, .ogg, .wav, .flac, .m4a, .aac, .mov, .avi, .mkv`

```python
    Then:   Сервер возвращает 206 Partial Content"""

        self.assertEqual(response.status_code, 200)

    def test_partial_request(self):
        response = self.client.get('/media/audio/test.mp3',
                                    HTTP_RANGE='bytes=0-1023')
        self.assertEqual(response.status_code, 206)
        self.assertIn('Content-Range', response)
        self.assertEqual(response['Content-Range'], 'bytes 0-1023/<size>')

    def test_416_out_of_range(self):
```

4. Ниже карты — сетка карточек. Кликните **«Подробнее»** на нужной.
5. На детальной странице:
   - Пролистайте галерею изображений (стрелки ‹ / ›).
   - Прочитайте описание объекта.
   - Если есть — посмотрите 360° панораму (перетаскивайте мышью или касанием).
   - Если есть — посмотрите видео.
   - Если есть — перетащите ручку слайдера, чтобы сравнить состояние «до» и «после» реставрации.
6. Чтобы открыть объект на Яндекс.Картах, нажмите **«🗺 Открыть карту»** в правой колонке.
7. Чтобы вернуться к списку, нажмите **«← Назад к списку объектов»**.

#### 6.3.2. Поиск информации

1. В правом верхнем углу страницы найдите **иконку 🔍** или поле «Поиск...».
2. Введите ключевое слово (например, `собор`, `деревянный`, `барокко`).
3. Нажмите **Enter** или кнопку **«Найти»**.
4. Откроется страница результатов с пагинацией (10 на страницу).

**Что ищется:**

- Краткое описание (`intro`)
- Описание объекта (`description`)
- Адрес (`address`)
- Содержимое StreamField (`content`)

4. На детальной странице:
   - Вверху — хлебные крошки для навигации.
   - Заголовок и дата публикации.

#### 6.3.5. Просмотр 360° панорамы

1. Перейдите на детальную страницу объекта с панорамой.
2. Прокрутите вниз до блока «360° Панорама» (чёрный контейнер).
3. Дождитесь загрузки (1-3 секунды).
4. **Управление:**

2. Введите логин и пароль, выданные администратором.
3. После входа — главная панель Wagtail со списком разделов.

#### 6.4.2. Создание нового объекта наследия

1. В дереве слева найдите **«Объекты историко-архитектурного наследия»**.
2. Нажмите **«Добавить дочернюю страницу» → «Объект историко-архитектурного наследия»**.
3. Заполните поля:
   - **Заголовок** — название объекта (например, «Успенский собор»).
   - **Slug** — URL-идентификатор (например, `uspenskiy-sobor`).
   - **Адрес** — почтовый адрес.
   - **Телефон**, **Описание**, **Год постройки**, **Архитектурный стиль** — по необходимости.
   - **Широта / Долгота** — для отображения на карте. Можно узнать через Яндекс.Карты (правый клик → «Что здесь?»).

   - Нажмите **«Добавить блок» → «Изображение»** для каждой фотографии.
   - Загрузите JPG/PNG, укажите alt-текст.
5. В разделе **«Контент»** (StreamField) добавьте блоки:
   - **Заголовок** (`heading`) — для подзаголовков.
   - **Параграф** (`paragraph`) — для текста.
   - **Изображение** (`image`) — для одиночных картинок.
   - **Видео** (`video`) — вставьте iframe YouTube/RuTube/VK.
   - **Документ** (`document`) — загрузите PDF.
   - **Сравнение** (`comparison`) — два изображения «до/после».
   - **360° Панорама** (`panorama`) — загрузите equirectangular JPG.
6. Нажмите **«Опубликовать»** вверху справа.

#### 6.4.3. Создание новости

1. В дереве найдите **«Новости»** (индексную страницу).

   - **Заголовок** новости.
   - **Дата публикации**.
   - **Изображение** — анонс (загрузите через Image Chooser).
   - **Краткое описание** (intro) — 1-2 предложения.
   - **Контент** (StreamField) — heading, paragraph, image, video.
4. Опубликуйте.

#### 6.4.4. Редактирование футера

1. В админке перейдите в **«Snippets»** (внизу меню).

3. Отредактируйте:

   - Адрес, email, телефон.
   - Ссылки на соц.сети (VK, YouTube, Telegram).
   - Контактное лицо и должность.
4. Нажмите **«Сохранить»**. Изменения мгновенно появятся на всех страницах.

#### 6.4.5. Загрузка большой панорамы (до 50 МБ)

1. При редактировании объекта в StreamField добавьте блок **«360° Панорама»**.
2. В поле «Файл панорамы» нажмите **«Choose an image»** → **«Upload»**.
3. Выберите JPG/PNG (equirectangular, 360°) размером до 50 МБ.
4. При необходимости укажите **заголовок** и **описание**.
5. Сохраните блок. Панорама автоматически появится на странице.

### 6.5. FAQ (Часто задаваемые вопросы)

**Q1. Не загружается 360° панорама. Что делать?**
> Проверьте: 1) Браузер поддерживает WebGL (Chrome, Firefox, Edge, Safari 14+). 2) Файл — equirectangular (2:1 соотношение сторон). 3) Размер ≤ 50 МБ. 4) В консоли браузера (F12) нет ошибок. Попробуйте другой браузер.

**Q2. Карта объектов не показывает метки. Почему?**
> Проверьте, что у объекта заполнены поля «Широта» и «Долгота». Координаты должны быть в десятичных градусах (например, 64.5399, 40.5150), а не в градусах-минутах-секундах.

**Q3. Как добавить видео с RuTube или VK?**
> Используйте блок «Видео» (VideoBlock) в StreamField. Скопируйте iframe-код с RuTube/VK (кнопка «Поделиться» → «Встроить») и вставьте в поле `video_embed`. Стили адаптивного контейнера применятся автоматически.

**Q4. Поиск не находит страницу. Почему?**
> Поиск работает по: заголовку, intro, description, address, year_built, architectural_style, содержимому StreamField. Проверьте: 1) Страница опубликована (`live=True`). 2) Запрос написан кириллицей (поиск регистронезависимый). 3) Слово присутствует в одном из перечисленных полей.

**Q5. Можно ли изменить цвета сайта без программиста?**
> Да, через шаблоны. Откройте нужный HTML-файл (например, `heritage_object_page.html`) и измените CSS-переменные в `<style>` (например, `--bs-primary: #0d6efd`). Или в общем `base.html` в `<head>`.

**Q6. Как сделать бэкап базы данных?**
> SQLite: просто скопируйте файл `db.sqlite3`. PostgreSQL: `pg_dump -U narfu narfu_heritage > backup.sql`.

**Q7. Как добавить новый раздел (например, «События»)?**
> Создайте модель в `home/models.py`, наследующую `Page`. Добавьте в `INSTALLED_APPS`. Зарегистрируйте через `wagtail.contrib.modeladmin` или в `INSTALLED_APPS` приложения. Создайте шаблон. Подробнее — [документация Wagtail](https://docs.wagtail.org/).

**Q8. Что делать, если сайт медленно работает?**
> 1) Проверьте нагрузку на сервер. 2) Включите кэширование (Django cache framework + Redis). 3) Оптимизируйте запросы к БД (`select_related`, `prefetch_related`). 4) Сожмите изображения (WebP). 5) Используйте CDN для статики.

**Q9. Как обновить Wagtail до новой версии?**
> 1) Прочитайте release notes. 2) Обновите `wagtail==7.X` в `requirements.txt`. 3) `pip install -r requirements.txt --upgrade`. 4) `python manage.py migrate`. 5) Запустите тесты. 6) Проверьте на dev-сервере, потом на prod.

**Q10. Куда писать об ошибках и предложениях?**

В ходе работы над проектом реализован полнофункциональный веб-портал объектов историко-архитектурного наследия на базе Django 6.0 + Wagtail 7.3. Система поддерживает:

- Контейнеризацию через Docker.
